# 별땅 (옛 이름 스타랜드, 저장소 starland) — Claude Code 작업 규칙

## 이 프로젝트
- 생일·기념일·전화번호의 숫자 8자리로 찾은 ‘우리나라 속 나의 별땅’에 별을 찍고, 행운 카드와 함께 선물하는 반응형 웹사이트. 국가지점번호를 알리는 것이 공익 목적이다.
- 사이트 이름 **별땅**(2026-10-14 스타랜드에서 바꿈), 내가 고른 땅 이름도 **별땅**. 첫 화면 제목은 `brand.js`의 HEADLINE(사용자가 직접 고치기도 함). 이름·첫 화면 문구는 `src/lib/brand.js` 한 곳에서 관리한다.
- 형제 사이트 ‘별지점’(저장소 `prepjoo/inyeon-geometry`)과는 **완전히 따로** 운영한다. 그쪽 코드를 고치지 않는다(2026-10-13 사용자 결정).
- 기준 문서: `docs/plan.md`(기획 요약, Claude 문서 ‘별지점 새 기획서 v5 초안’을 옮김), `docs/changes.md`(이후 바뀐 결정, 기획서보다 우선). 두 문서와 이 파일이 충돌하면 멈추고 사용자에게 묻는다.
- 디자인: 시안 C ‘엽서와 우표’. 흰 바탕·잉크색(#222034) 글자, 제목 Do Hyeon·본문 Gothic A1(@fontsource, SIL OFL). 내 별땅 노랑 #ffc145, 우리 별땅 분홍 #ff8fa8, MBTI 별땅 민트 #5ed3c3(흰 바탕 위 글자는 `--accent-ink`), 국가지점번호는 초록 점선 우표, 긴급 신고는 빨강.
- 주메뉴 3개(`lib/flows.js`): **내 별땅 분양받기**(#/mine/1·2, 생일·전화번호·숫자) · **우리 별땅 분양받기**(#/us/1·2, 기념일. 1단계 화면(우리 별땅 메인) 아래에 ‘우리 둘 만남 별자리’) · **MBTI 별땅 분양받기**(#/mbti/1·2, 두 사람 MBTI 8글자 → 숫자 8자리 → 추천 별, 날짜 없음). 이어서 #/land 내 별땅 → #/g?… 선물 받은 화면. #/ 첫 화면(제목·별땅문서 예시 그림 + 메뉴 3개 + 오늘의 행운 + 기억하는 기념일 D-day), #/archive 보관함, #/learn 국가지점번호란?, #/here 내 위치 국가지점번호, #/sos 긴급 신고.
- 머리: 로고 + 아이콘 메뉴 5개(내·우리·MBTI 별땅, 보관함, 국가지점?) + **오른쪽 위 작은 [내 위치]·[긴급 신고]**. 날짜는 연대→년→월→일 고르기(`components/DateSelect.jsx`, 최근 연도는 보는 날 기준으로 저절로 늘어남). 내 별땅의 숫자 입력 이름은 ‘의미 있는 수’, 전화번호 칸은 ‘010-’이 미리 들어가 있다. ‘분양’은 놀이 표현이며 무료·기념 표시라고 안내한다. 첫 화면 메뉴 칸은 홍보 카피(hook)와 설명만(메뉴 이름은 머리 아이콘·1단계 화면에, `lib/flows.js`). 별땅 결과의 카드는 ‘이 땅의 행운 카드’(수호 카드)만. 오늘의 행운 카드와 행운의 번호 3개(1~45)는 첫 화면 ‘오늘의 행운’에서 하루 한 번 바뀐다. [내 별땅으로 확대]는 최대 확대에서 10m 칸만 보이고 ‘실제 분양이 아닌 기념 표시’ 안내를 붙인다. 이미지는 ‘별땅문서’(캔버스로 그림, 나눔명조, 분양 사유 대신 헌사 한 문장 `engine/dedication.js`, 놀이용·법적 효력 없음 문구 필수).
- 지금은 1단계만 만든다. 2단계(익명 숫자 “이 동네에 별 37개”)·3단계(동갑 마을·구역 모임 커뮤니티)는 계획에만 있다 — 사용자 승인 없이 시작하지 않는다.

## 사용자에 대해
- 기획자는 60대 비개발자다. 설명은 쉬운 한국어로, 전문용어는 풀어서 쓴다.
- 명령어(npm install 등)는 사용자에게 시키지 말고 Claude가 직접 실행한다.
- 작업은 짧은 계획을 먼저 적어 두고 바로 진행한다. 되돌리기 어려운 결정(공개 배포, 데이터 출처 계약, 기획 변경)만 승인을 받는다.
- 작업이 끝나면 "무엇이 바뀌었는지, 어떻게 확인하는지"를 3줄 안으로 알려준다.

## 기술 스택
- Node.js 22 LTS, React 19, Vite 8, Leaflet 1.9 + react-leaflet 5, proj4 2.22. 테스트: Vitest(단위), Playwright(브라우저).
- 저장소: GitHub `prepjoo/starland`. 공개 주소: https://starland-lovat.vercel.app (2026-10-14 첫 배포, starland.vercel.app은 다른 회사 것). 배포: Vercel(GitHub 연결, 정적 사이트, `vercel.json`에 보안 헤더). main에 합치면 공개 주소, 브랜치마다 미리보기 주소.
- 해시 라우팅. 서버·데이터베이스·회원가입·결제 없음. 개인 입력(번호·MBTI)은 어떤 저장소에도 올리지 않는다.

## 반드시 지킬 규칙
1. **파일·폴더 이름은 영문만.** 화면의 한글은 그대로 둔다.
2. **계산 엔진은 `src/engine/`에 순수 함수로.** 같은 입력이면 항상 같은 결과. 화면 코드에 계산을 넣지 않는다. 엔진 함수는 테스트를 먼저 쓴다.
3. **별땅 규칙:** 8자리 = 국가지점번호 숫자(앞 4자리 동쪽, 뒤 4자리 북쪽, ×10m). 64구역마다 한 곳씩 있고 육지(시·군·구 경계 안)만 후보로 보여 준다(보통 10곳, 6~13곳). 사용자가 하나를 고른다.
   - 날짜는 YYYYMMDD, 전화번호는 숫자만 모아 마지막 8자리. 숫자는 문자열로 다룬다(앞자리 0 유지).
   - MBTI 8자리 = 두 사람 MBTI를 알파벳순으로 이어 휴대폰 자판 숫자로(E3 I4 S7 N6 T8 F3 J5 P7, 예: ESTJ+INFP → 3785 4637). 추천 별 = SHA-256('v5-couple' | 두 MBTI 가나다순 | 8자리) % 후보 수. 놀이용 추첨이며 궁합을 평가하지 않는다(메뉴 문구에 ‘궁합’이라는 말은 써도 됨, 사용자 결정 2026-10-14. 점수·좋고 나쁨은 보여 주지 않는다).
4. **행운 카드:** 타로 메이저 22장, 라이더-웨이트-스미스 정방향 전통 해석만(근거 없는 새 해석 금지). 수호 카드 = 8자리 합을 21 이하가 될 때까지 자릿수 합. 오늘의 행운 카드 = 첫 화면에서 하루 한 장, 씨앗값 SHA-256('v5-daily' | 한국 날짜 | 이 기기의 무작위 값)으로 카드와 행운의 번호 3개(1~45, 놀이용·당첨과 무관)를 뽑는다(`engine/daily.js`, 사용자 결정 2026-10-14. `drawTodayCard`·옛 ‘올해의 카드’ 함수는 남겨 둠). 계산법 출처는 ‘확인 필요’. 행운의 방향 = 카드 번호 × 360/22°(0번 정북, 시계 방향).
5. **선물 링크:** `#/g?n=<구역+8자리>&m=<가림>&t=<한 줄 60자>`만 담는다(예전 링크의 c·y는 읽기만). MBTI·번호 종류·날짜는 담지 않는다. 보내기 전 동의 확인 필수.
6. **국가지점번호:** UTM-K(EPSG:5179). 첫 글자 = 동서 100km 구역(700,000m부터 가·나·다…), 둘째 글자 = 남북 100km 구역(1,300,000m부터 가·나·다…), 숫자는 구역 경계로부터 10m 단위 4자리+4자리. 화면에는 항상 ‘계산값’. 테스트 기준값: 서울시청 앞 다사 5390 5203, 부산시청 인근 마라 4341 8830, 한라산 정상 인근 다나 0986 8599(공식 조회 대조 전, 확인 필요).
7. **개인정보:** MBTI 글자는 서버·주소창·로그·이미지·보관함 어디에도 남기지 않는다. 다만 MBTI 별땅 번호는 자판 숫자라 거꾸로 읽으면 두 사람 MBTI를 알 수 있으므로, 선물 전 동의 문구에 그렇게 알린다(사용자 결정 2026-10-14). 번호는 이 기기 안에서만 계산하고, 보내는 사람이 동의했을 때만 선물 링크·이미지에 별땅 번호로 나간다. 전화번호는 기본으로 가운데를 가리고(57●● ●●88) 지도 위치로 알아낼 수 있다고 안내한다. 기념일 날짜는 [기념일로 기억하기] 때만 이 기기에 저장하고 [모두 지우기]를 둔다. CSP로 접속처를 이 사이트와 지도 타일 서버로 제한한다.
8. **위치:** 사용자가 오른쪽 위 작은 버튼 [내 위치](#/here) 또는 [긴급 신고](#/sos)를 눌렀을 때만 위치를 요청한다. 위치는 화면에서만 쓰고 저장·전송하지 않는다. 긴급 신고 화면 순서는 ① 119에 문자로 내 위치 보내기(가장 큰 버튼) ② 가족·지인에게 위치 보내기(공유/복사) ③ 전화 신고 119·112(작게 나란히, ‘전화로 이렇게 읽어 주세요’ 문장 함께) ④ 지금 내 위치 자세히(사용자 결정 2026-10-14). 위치를 못 찾으면 전화로 안내하고, 오차가 100m를 넘으면 경고한다. 122는 공식 확인 전이라 뺀다. 신고 문자는 ‘국가지점번호 ○○ (휴대폰 계산값)’을 맨 위에, 오차·측정 시각, 위경도는 아래에 참고로 넣는다(사용자 결정 2026-10-14). 화면에는 ‘전화로 이렇게 읽어 주세요’ 문장(숫자를 한 자리씩)을 보여 준다.
9. **별땅은 기념 표시:** “실제 토지 소유권과 관계없는 기념 표시, 찾아가지 마세요”를 항상 보여 준다. 로또는 만들지 않는다(‘로또’라는 말·6개 번호·판매점 안내 금지. 행운의 번호 3개는 놀이용 표시만).
10. **우리 둘 만남 별자리(사용자 승인 2026-10-14):** 우리 별땅 1단계 화면(메인)에서, 날짜 없이도 바로 쓴다. 고른 날짜의 수호 카드 방향, 날짜가 없으면 오늘 날짜의 수호 카드 방향. ‘만날 장소까지 거리’ 걸어서 1.5·가까운 곳 6(기본)·조금 먼 곳 15·당일치기 60km(직선거리, `MEET_RANGES`): 같은 동네는 별 반지름 = 거리×0.6, 두 동네는 빈 꼭짓점이 가까운 출발점에서 거리 안인 별만(없으면 가장 가까운 별 + 안내). A·B는 ‘내가/상대가 출발하는 지점’이라고 부른다. 두 사람 시·군·구 대표 지점(`engine/anchor.js`) A·B를 변·대각선으로 하는 정오각형 4개 중 수호 카드 방향에 가장 가까운 것 → 빈 꼭짓점 3개마다 가장 가까운 **공개 장소**(한국관광공사 TourAPI, `places-<시도>.json`) → 만남 장소 1·2·3, 각 장소 근처 음식점·카페 2곳(`food-<시도>.json`, 1.5→5→10km).  별땅(가지 마세요)과 만남 장소(가 볼 수 있음)를 화면에서 분명히 나눈다. 선은 상징이고 실제 길이 아님, 광고 아님·운영 여부 확인 안내. 고른 동네는 저장·전송하지 않는다. 민간 평가 목록(미슐랭 등)은 쓰지 않는다.

## 작업 방식
- 작업을 마칠 때마다 `npm test`와 `npm run build`를 실행해 통과를 확인한 뒤 보고한다. 화면을 바꿨으면 `npm run test:e2e`(휴대폰·PC·접근성)도 돌린다. 이 작업 환경에서는 `PW_CHROMIUM=/opt/pw-browsers/chromium`을 앞에 붙인다. 실패한 채로 "완료"라고 하지 않는다.
- 기획이 바뀌면 `docs/`와 이 파일도 함께 고친다.
- 확인되지 않은 사실(공식 번호, 계산법 출처, 상표 등)은 추측하지 말고 "확인 필요"로 남긴다.
